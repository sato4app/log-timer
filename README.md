## log-timer - 運動の記録用アプリ

タバタ式インターバルに対応した運動タイマーです。
「準備 → 運動 → 休憩」を指定した回数だけ繰り返します。
PWA なのでスマホのホーム画面に追加でき、オフラインでも動きます。

### 機能

- **時間・回数の設定**（実行中は変更不可）
  | 項目 | 既定値 | 範囲 |
  | --- | --- | --- |
  | 準備 | 10 秒 | 0〜599 秒 |
  | 運動 | 20 秒 | 1〜599 秒 |
  | 休憩 | 5 秒 | 0〜599 秒 |
  | 回数 | 3 回 | 1〜99 回 |
  「既定値に設定」で今の設定を既定値として保存できます（次回の起動時もその値で立ち上がります）。「既定値に戻す」で保存した既定値に戻ります。
- **表示方法の切り替え**: ↓ アイコン = カウントダウン（残り時間）／↑ アイコン = カウントアップ（経過時間）
- 進捗リングとフェーズ別の背景色（準備=青 / 運動=赤 / 休憩=緑 / 完了=紫）
- **音の鳴らし方**: 画面右上のボタンで「音声 → 電子音 → 音 オフ」と切り替わります（選んだ方式は次回の起動時も引き継ぎます）
  - **音声**: フェーズの切り替えはどれも読み上げます（「準備」「運動 2 回目」「休憩」「終了。お疲れさまでした」）
    - 秒読みを読み上げるのは運動だけで、フェーズの最初から最後まで毎秒読みます。数字は画面の数字に合わせます（運動 20 秒の場合）
      - カウントダウン表示: 「20」「19」…「1」「0」
      - カウントアップ表示: 「1」「2」…「19」「20」
    - 最後の「0」（「20」）は運動が終わる瞬間に読むので、次の「休憩」「終了。お疲れさまでした」はそれを言い終えてから始まります（そのぶん少し遅れます）
    - 準備と休憩の秒読みは、どちらの表示でも残り3秒からの電子音（数字は読みません）
  - 秒読みは「運動 ○ 回目」を言い終えてから始まるので、頭の1〜2秒（カウントダウンなら「20」「19」）は飛びます。フェーズ名が途中で切れることはありません
  - **電子音**: フェーズごとに高さが違うビープ音。数字を読まないので、どちらの表示でも残り3秒から「ピッ・ピッ・ピッ」と鳴らし、フェーズの終わり（カウントダウンの0）だけトーンを上げて長めに「ポーン」と鳴らします（時報と同じ区切り方）。次のフェーズの合図は、それと重ならないよう少し遅らせて鳴ります
    - 「音声」を選んでいるときの準備・休憩の秒読みも同じ鳴り方です
  - 読み上げは端末内蔵の音声を使うため追加ファイルは不要で、オフラインでも鳴ります。読み上げに対応していないブラウザでは「音声」は選択肢に出ません
- 一時停止・再開・リセット
- **実行履歴**: 最後まで終えた実行を日時・表示方法（↑ カウントアップ / ↓ カウントダウン）・設定（準備 / 運動 / 休憩 / 回数）で1行ずつ記録。行をタップするとその設定で再実行できます（端末内に最大50件保存）
- **日ごとの実施回数**: 履歴右上のカレンダーアイコンで月表示に、リストアイコンで一覧に戻ります。実施した日にその日の回数を表示し、月の合計も出ます（前後の月へは ‹ › で移動）
- **QRコード**: 画面右上の「QR」ボタンで、このページのURLをQRコードで表示します。別の端末のカメラで読み取ってもらえば、同じアプリをすぐ開けます（どこをタップしても閉じます）
- 実行中は画面のスリープを抑止（対応ブラウザのみ）
- **更新の確認**: 画面左上の「log-timer」をタップすると、端末に入っている版とサーバー側の版を見比べます。違っていれば新しい版を取り込んで読み込み直し、同じなら「最新です（v8）」と数秒だけ表示します（見た目はタイトルのままで、ボタンには見えません）。実行中の記録が消えないよう、タイマーを走らせている間は確認しません
- キーボード操作: スペースキー = 開始 / 一時停止、R キー = リセット

準備や休憩を 0 秒にすると、そのフェーズは読み飛ばされます。

### スマホで使う

**Service Worker は HTTPS か localhost でしか動きません。**
PC のローカルサーバーに LAN 経由（`http://192.168.x.x:8000` など）でアクセスすると
タイマーは動きますが、ホーム画面への追加とオフライン実行はできません。
スマホで PWA として使うには HTTPS で配信してください。

GitHub Pages を使う場合（このリポジトリは `sato4app/log-timer`）:

1. GitHub にプッシュする
2. リポジトリの Settings → Pages で Source を `main` ブランチのルートに設定する
3. スマホのブラウザで `https://sato4app.github.io/log-timer/` を開く

ホーム画面への追加:

- **Android (Chrome)**: 画面右上の「ホーム画面に追加」ボタン、またはメニューの「アプリをインストール」
- **iPhone (Safari)**: 共有ボタン → 「ホーム画面に追加」
  （iOS は追加ボタンを自動表示できないため手動操作が必要です）

追加後は全画面（standalone）で起動し、機内モードでも動作します。

### PC で動かす（開発時）

`app.js` を Babel が読み込むため、`file://` で直接開くと動作しません。
ローカルサーバーを起動してください。

```bash
python -m http.server 8000
# または
npx serve .
```

ブラウザで http://localhost:8000 を開きます。

### ファイル構成

| ファイル | 内容 |
| --- | --- |
| `index.html` | CDN 読み込み、PWA 用メタタグ、マウント先 |

### 技術

- React 18（CDN / UMD）
- Tailwind CSS（CDN）
- Babel standalone（ブラウザ内で JSX を変換）
- Web Audio API（電子音）、Web Speech API / SpeechSynthesis（読み上げ）、Screen Wake Lock API（スリープ抑止）

計時は `setInterval` のカウントではなく終了時刻（実時刻）との差分で行うため、
タブが裏に回っても時間がずれません。

CDN から読み込むライブラリも Service Worker がキャッシュするため、
2 回目以降の起動はオフラインでも完結します。
ファイルを更新したときは `service-worker.js` の `CACHE_NAME` の版数を上げてください。
古いキャッシュが破棄されて新しいファイルに入れ替わります。

版数を書くのはこの1箇所だけです。タイトルをタップしたときの更新確認は、
端末側の版を Service Worker に聞き、サーバー側の版を `service-worker.js` から読み取って見比べます。
