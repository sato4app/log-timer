# log-timer 機能仕様書

**バージョン:** v18（`service-worker.js` の `CACHE_NAME = 'logtimer-v18'`）
**最終更新日:** 2026年10月1日

---

## 1. 概要

### 1.1 アプリケーション名
log-timer（PWA名: log-timer - 運動タイマー／ホーム画面の表示名: log-timer）

### 1.2 目的
タバタ式に代表されるインターバルトレーニング用のタイマー。
「準備 → 運動 → 休憩」を指定した回数だけ繰り返し、フェーズの切り替えと終わり際を音声または電子音で知らせる。
最後まで終えた実行を端末内に記録し、一覧と月カレンダーで振り返れる。
PWA としてホーム画面に追加でき、2回目以降の起動はオフラインで完結する。

### 1.3 動作環境
- **プラットフォーム:** Webブラウザ（PWA対応）
- **必須環境:** HTTPS または localhost（Service Worker の要件）。`file://` では Service Worker が動かないため、オフライン動作とホーム画面への追加はできない
- **任意の機能と必要な API**
  | 機能 | API | 非対応のとき |
  | --- | --- | --- |
  | 読み上げ | Web Speech API（`speechSynthesis` / `SpeechSynthesisUtterance`） | 音の切り替えに「音声」が出ない |
  | 電子音 | Web Audio API（`AudioContext` / `webkitAudioContext`） | 音が出ないだけでタイマーは動く |
  | スリープ抑止 | Screen Wake Lock API | 抑止しないだけでタイマーは動く |
  | 設定・履歴の保存 | `localStorage` | 保存されないだけでタイマーは動く |

## 3. 設定

### 3.1 設定項目
| 項目 | 組み込みの既定値 | 範囲 | 単位 |
| --- | --- | --- | --- |
| 準備 | 10 | 0〜599 | 秒 |
| 運動 | 20 | 1〜599 | 秒 |
| 休憩 | 5 | 0〜599 | 秒 |
| 回数 | 3 | 1〜99 | 回 |

- 入力欄（`NumberField`）
  - フォーカスすると空欄になり、元の値は薄い文字（placeholder）で見える
  - Enter またはフォーカスを外したときに確定する。範囲外は範囲内に丸め、数字でなければ元の値に戻す
  - ＋ − ボタンで 1 ずつ増減する。上限・下限ではそれぞれのボタンを押せなくする
- タイマーが動いている間は入力できない（一時停止中は入力できる。反映のしかたは 4.5）
- 待機中に値を変えると、円の中の秒数も最初のフェーズの長さに合わせて変わる
- 設定欄の右上に合計時間を「合計 m分ss秒」で出す。
  計算式は `準備 + 回数 × 運動 + (回数 − 1) × 休憩`（最後の運動のあとに休憩は入らない）

### 3.2 既定値の保存と復元
- **既定値に設定:** 今の設定を既定値として `localStorage` に保存する。次回の起動時はこの値で立ち上がる
- **既定値に戻す（準備/運動/休憩/回数回）:** 保存した既定値に戻す。ボタンには既定値の中身を出す
- どちらも、タイマーが動いている間と、今の設定が既定値と同じときは押せない
- 保存した既定値が壊れているとき（数字でない、範囲外）は、項目ごとに組み込みの既定値または範囲内の値に直して使う

### 3.3 表示方法（カウントダウン／カウントアップ）
| ボタン | 意味 | 円の中の秒数 | 進捗リング |
| --- | --- | --- | --- |
| ↓ | カウントダウン（残り時間） | 残り秒の切り上げ（N…1） | 満ちた状態から減る |
| ↑ | カウントアップ（経過時間） | 経過秒の切り捨て（0…N−1） | 空から増える |

- 選んでいる方のボタンを白く反転する。タイマーの実行中でも切り替えられる
- 60秒以上は `m:ss` で表示する
- 表示方法は保存しない。起動時は常にカウントダウン（↓）

## 4. タイマーの進行

### 4.1 フェーズの流れ
```
準備 → 運動(1回目) → 休憩 → 運動(2回目) → … → 運動(N回目) → 完了
```
- 準備・休憩が 0 秒のときは、そのフェーズを飛ばす（準備が 0 秒なら運動から始まる）
- 最後の運動のあとは休憩を挟まずに完了する
- 円の下に「n / N 回目」を、完了後は「全 N 回 終了」を出す

### 4.2 操作
| 操作 | ボタン | 動作 |
| --- | --- | --- |
| 開始 | スタート | 待機・完了の状態から、今の設定で最初から始める |
| 一時停止 | 一時停止 | 残り時間を控えて止まる。読み上げを止め、スリープ抑止を解く |
| 再開 | 再開 | 控えた残り時間から続ける |
| リセット | リセット | 待機に戻す（1回目、残り時間は最初のフェーズの長さ）。読み上げを止め、スリープ抑止を解く |

ボタンの表示は、動いている間は「一時停止」、待機・完了のときは「スタート」、一時停止中は「再開」。

### 4.3 計時方式
- フェーズの終了時刻（実時刻）を持ち、100ms ごとに現在時刻との差で残り時間を求める。
  タブが裏に回って間隔が乱れても時間はずれない
- 残りが 0 以下になったら、フェーズ最後の合図を鳴らして次のフェーズへ進む

### 4.4 画面スリープの抑止
- 開始・再開のときに Screen Wake Lock を取る
- 実行中に画面が裏から戻ったとき（`visibilitychange`）に取り直す
- 一時停止・リセット・完了で解く

### 4.5 一時停止中の設定変更
- 一時停止中に変えた値は、**次のフェーズから**使う。一時停止したフェーズは、入った時点の長さのまま最後まで進める
- フェーズの長さはフェーズに入った時点で控え（`phaseLen`）、円の中の秒数・進捗リング・運動の秒読みはこの長さで求める。
  そのため設定を変えても、数字と円の進み具合はずれない
- 回数は、今の回より少なくできない（休憩中は、次の運動の回まで残す）。＋ − と直接入力のどちらでもこの下限で止める
- 合計時間（3.1）は、変えた後の設定で計算し直す
- 完了時に履歴へ残す設定は、完了した時点の設定

## 5. 音

### 5.1 音の方式
ヘッダーのボタンで「音声 → 電子音 → 音 オフ」の順に切り替わる。ボタンには今の方式を出す。
選んだ方式は `localStorage` に保存し、次回の起動時に引き継ぐ。
読み上げに対応していないブラウザでは「音声」を飛ばし、「電子音 → 音 オフ」の2択になる。

| 方式 | フェーズの切り替え | 運動の秒読み | 準備・休憩の秒読み |
| --- | --- | --- | --- |
| 音声 | 読み上げ | 毎秒読み上げ | 電子音（5.3） |
| 電子音 | 電子音 | 電子音（5.3） | 電子音（5.3） |
| 音 オフ | なし | なし | なし |

### 5.2 音声（読み上げ）
- 端末内蔵の音声で読み上げる（`lang = ja-JP`、速さ 1.15）。追加ファイルは使わず、オフラインでも鳴る
- フェーズ名: 「準備」「運動 n 回目」「休憩」、完了時は「終了。お疲れさまでした」
- 運動の秒読み: フェーズの最初から最後まで毎秒、画面の数字に合わせて読む（運動 20 秒の例）
  - カウントダウン: 「20」「19」…「1」、終わる瞬間に「0」
  - カウントアップ: 「1」「2」…「19」、終わる瞬間に「20」
- フェーズ名を読み終えるまでは秒読みを見送り、読み終えた時点の秒から再開する。
  そのため運動の頭の1〜2秒の数字は読まない。読み終わりは `onend` で拾い、
  届かないブラウザでも止まらないよう `400 + 文字数 × 130` ms の見込みでも解除する
- 運動の最後の数字を読んだときは、次のフェーズ名をその後ろにつなげて読む（前の読み上げを打ち切らない）
- 新しい数字を読むときに前の読み上げが残っていれば打ち切る

### 5.3 電子音
Web Audio API のサイン波。音量 0.4 から減衰させて止める。

| 合図 | 周波数 | 長さ | 鳴らすとき |
| --- | --- | --- | --- |
| 秒読み | 784 Hz | 0.1 秒 | 残り 3・2・1 秒 |
| フェーズ最後 | 1175 Hz | 0.25 秒 | 残り 0 秒（フェーズが終わる瞬間） |
| 準備・休憩の始まり | 660 Hz | 0.25 秒 | フェーズの開始時 |
| 運動の始まり | 880 Hz | 0.25 秒 | フェーズの開始時 |
| 完了 | 1046 Hz → 1318 Hz | 0.35 秒 → 0.5 秒 | 完了時（2音目は 200ms 後） |

- 秒読みは、カウントダウン・カウントアップのどちらの表示でも残り3秒から鳴らす（数字を読まないため）
- フェーズ最後の合図を鳴らしたときは、次のフェーズの合図を 250ms 遅らせて重ならないようにする
- 「音声」を選んでいるときも、準備・休憩の秒読みとフェーズ最後の合図はこの電子音で鳴らす
- 完了の2音目は「電子音」を選んでいるときだけ鳴らす

### 5.4 iOS 向けの音の準備
iOS は利用者の操作を起点にしないと音が出ないため、スタート・再開・音の切り替えの操作の中で次を行う。
- `AudioContext` を用意し、止まっていれば（`suspended` / `interrupted` など `running` 以外）再開させる。閉じていれば作り直す
- 無音の音を1つ鳴らして、音の出口を開いておく
- 「音声」のときだけ、無音の読み上げを1つ通しておく
  （「電子音」のときに読み上げを通すと、iOS では音の受け持ちが読み上げ側に移り、電子音が鳴らなくなるため）

音が出せない環境でも、例外は握りつぶしてタイマーは動かし続ける。

## 6. 実行履歴

### 6.1 記録
- 最後まで終えた（完了した）実行だけを記録する。途中でリセットした実行と、ガイドの試し実行は記録しない
- 新しい順に最大 50 件を `localStorage` に保存し、超えた分は古いものから捨てる
- 記録する内容は日時・準備・運動・休憩・回数・表示方法（7.2）

### 6.2 一覧
- 列: 日時（`yyyy/mm/dd hh:mm`）、準備、運動、休憩、回数、表示方法（↑ / ↓ のアイコン）
- 表示方法を持たない古い記録は、矢印の欄を空欄にする
- 記録がないときは「最後まで実行すると、ここに記録されます」と出す
- 行をタップすると、その記録を読み込む（6.3）。タイマーが動いている間はタップできない

### 6.3 記録の読み込み
- 準備・運動・休憩・回数を設定に入れる（範囲外の値は範囲内に丸める）
- 記録に表示方法があれば、↑ / ↓ もそれに合わせる。なければ今の表示方法のまま
- 状態を待機に戻す（1回目、残り時間は読み込んだ設定の最初のフェーズ）。一時停止中や完了後に読み込んでも最初からになる
- 読み込むだけで、開始はしない。開始はスタートボタンで行う

### 6.4 全消去
- 履歴の見出しの右の「全消去」で、記録をすべて消す。消す前に確認（`window.confirm`）で
  「履歴をすべて消去します。元に戻せませんが、よろしいですか？」と聞き、キャンセルなら何もしない
- 記録が1件もないときは出さない。タイマーが動いている間は押せない

### 6.5 日ごとの実施回数（月カレンダー）
- 履歴の見出しの右のアイコンで切り替える（リスト = 一覧、カレンダー = 月表示）。選んでいる方を白く反転する
- カレンダー表示中は設定欄を隠し、その分カレンダーを広く使う
- 記録を端末の日付（ローカル時刻）ごとに数え、各日のマスに印を出す
  | 回数 | 印 |
  | --- | --- |
  | 0 | なし |
  | 1〜3 | ☆ を回数分（☆ / ☆☆ / ☆☆☆） |
  | 4以上 | ☆ と回数（☆4、☆5 …） |
- 実施した日はマスを明るくし、今日のマスは枠で囲む
- 見出しに「yyyy年m月　計 n 回」を出す。‹ › で前後の月へ移る。開いたときは今月
- 曜日の見出しは日曜を赤、土曜を青で出す
- 数えるのは保存されている最大 50 件の範囲

## 7. データ保存

### 7.1 `localStorage` のキー
| キー | 内容 | 値 |
| --- | --- | --- |
| `logtimer-sound` | 音の方式 | `'voice'` / `'beep'` / `'off'`。不正な値なら選べる方式の先頭（読み上げ対応なら音声、非対応なら電子音） |
| `logtimer-defaults` | 既定値 | `{ prepare, work, rest, sets }`（数値） |
| `logtimer-history` | 実行履歴 | 7.2 の配列（新しい順、最大 50 件） |
| `logtimer-guide` | ガイドを出したかどうか | `'seen'` |

いずれも、読み書きに失敗したとき（壊れたデータ、`localStorage` が使えない環境）は例外を外に出さず、
既定の扱い（組み込みの既定値、履歴なし、ガイドは出さない）に戻す。

### 7.2 履歴の1件
| フィールド | 型 | 内容 |
| --- | --- | --- |
| `id` | number | 記録した時刻（epoch ms）。一覧の key に使う |
| `at` | string | 記録した日時（ISO 8601） |
| `prepare` | number | 準備（秒） |
| `work` | number | 運動（秒） |
| `rest` | number | 休憩（秒） |
| `sets` | number | 回数 |
| `countUp` | boolean | 実行時の表示方法（`true` = カウントアップ）。古い記録にはない |

## 8. 使い方ガイド

### 8.1 表示
- ヘッダーの「使い方」で開く。タイマーが動いている間は押せない
- 初めて開いたときは自動で出す。出した時点で「見た」ことにして、途中で閉じても次回からは出さない
- 開くとき、カレンダー表示中なら一覧に戻す（設定欄を指せるようにするため）

### 8.2 しくみ
- 説明する場所を光らせ、それ以外を暗くする。暗い部分は操作を受け付けず、光っている場所はそのまま押せる
- 吹き出しは、対象が画面の上半分なら下に、下半分なら上に出す（「音の鳴らし方」のページは画面下に固定）
- 画面の作りや窓の大きさが変わったときは、光らせる範囲を測り直す
- 吹き出しのボタン: 「閉じる」「戻る」（1ページ目では押せない）「次へ」（最後のページは「終わり」）
- キーボード: → で次へ、← で戻る、Esc で閉じる

### 8.4 試し実行（「音の鳴らし方」のページ）
- 「音を聞いてみる（12秒）」で、準備2秒・運動4秒・休憩2秒・2回の設定で実際にタイマーを動かす。実行中はボタンが「試し実行を止める」になる

## 10. 更新の確認

### 10.1 操作
- タイトル「log-timer」をタップすると、端末の版とサーバーの版を見比べる（見た目はタイトルのままでボタンに見えない）
- 結果はタイトルの右に出し、4秒で消す（「…」で終わる途中経過は消さない）

| 表示 | 状況 |
| --- | --- |
| 確認中… | サーバーに問い合わせ中（この間の二度押しは無視） |
| 実行中は確認しません | タイマーが動いている（読み込み直すと実行中の記録が消えるため） |
| 確認できません | オフラインなどでサーバーの版を取れない |
| 最新です（vN） | 同じ版だった。または端末にキャッシュがない（毎回ネットワークから読んでいる） |
| 更新中… | 版が違ったので入れ替えて読み込み直す |

### 10.2 版の求め方
- **サーバーの版:** `service-worker.js` をキャッシュを使わずに取得し、`CACHE_NAME = '...'` を読み取る
- **端末の版:** 起動時に、受け持ちの Service Worker に `MessageChannel` で問い合わせる（1.5秒で返事がなければ諦める）。
  受け持ちがいなければ、端末にある `logtimer-` で始まるキャッシュの名前を使う

### 10.3 入れ替え
- Service Worker を登録していれば、`update()` で新しい版を取り込み、待機中のものに `skip-waiting` を送り、
  受け持ちが引き継がれるのを待って（最長3秒）読み込み直す
- Service Worker がない環境では、`logtimer-` のキャッシュを消してから読み込み直す

iOS 向けに `apple-touch-icon`（180px）と `apple-mobile-web-app-*` のメタタグを `index.html` に置く。

### 11.2 ホーム画面への追加
- ブラウザが `beforeinstallprompt` を出したとき（Android の Chrome など）だけ、ヘッダーに「ホーム画面に追加」を出す。
  押すとブラウザの追加画面を開き、結果に関わらずボタンを消す。追加が済んだとき（`appinstalled`）も消す
- iOS はこのイベントがないため、Safari の共有ボタンから手動で追加する

### 11.3 Service Worker のキャッシュ戦略
| 対象 | 戦略 |
| --- | --- |
| インストール時 | アプリ本体（`./`、`index.html`、`app.js`、`styles.css`、`manifest.json`、アイコン3つ）を1つずつキャッシュ（1つ失敗しても他は入れる）。すぐに有効化する |
| 有効化時 | 今の `CACHE_NAME` 以外のキャッシュを消し、開いているページを受け持つ |
| `service-worker.js` 自身 | キャッシュを挟まない（古い版を返すと更新に気づけないため） |
| ページ遷移 | ネットワーク優先。取れなければキャッシュ、それもなければ `index.html` |
| 同じオリジンのファイル | キャッシュを即返し、裏でネットワークから取り直してキャッシュを更新 |
| CDN（React / qrcode-generator） | キャッシュ優先。なければ取得してキャッシュに入れる（`crossorigin` 付きで読むので、状態 200 の応答だけを入れる） |

- ページからのメッセージ: `'cache-name'` には版（`CACHE_NAME`）を返し、`'skip-waiting'` で待機中の版に入れ替える
- 版数を書くのは `service-worker.js` の `CACHE_NAME` だけ。ファイルを更新したら版数を上げる
